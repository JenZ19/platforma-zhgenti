## Порядок

- [ ] Блок 1: вход в обучение, установка, сервер и API; сервис-планер и агент планирования.
- [ ] Блок 2: остальные бытовые проекты по очереди.
- [ ] Блок 3: личные и клиентские агенты; индивидуальные сценарии и проверяемые подключения.

## Первый проверяемый выпуск

1. Добавить тесты `app/content/reviewed-planning.test.ts`: первый рабочий результат на первом шаге; 9 шагов сервиса и 10 агента; персонализация после создания; нет обязательной клиентской копии; реальные данные не заменяются примерами; публикация отделена от локального хранения. Запустить до реализации и убедиться в падении.
2. Ввести предметные маршруты `app/content/reviewed/planning.ts`. Обойти старую цепочку дописывания общих требований только для этих двух проектов. Сохранить остальные маршруты без изменения.
3. Перенести клиентскую практику в раскрываемый дополнительный блок последнего урока; показывать настройку на явно указанном шаге, а не безусловно на втором.
4. Для мобильного планера сохранить конкретные действия, один адресат технических команд — выданный помощник школы; убрать неоднозначную ссылку Lovable. Не превращать ручную проверку в команду помощнику.
5. При сокращении маршрутов переносить старые отметки по соответствию задач, не по номеру; исходную запись не перезаписывать при чтении. Проверить отдельные desktop/mobile и service/agent ключи, повторное сохранение и экспорт.
6. В основном маршруте показать вход через установку либо получение помощника. Сервер и API нужны по запросу проекта, не обязательная покупка для всех.
7. Улучшить подготовительные шаги без смены внешних продуктов и непроверенных обещаний. Сохранить реальные снимки и места для их замены.
8. После каждого маршрута — предметные тесты. Перед выпуском — все unit-тесты, lint, production build, проверка интерфейса и копируемых команд. Не отмечать внешние установки и платёжные операции выполненными.

## Ограничения

Сохраняем розовый дизайн и обложки. Новые схемы интерфейсов внешних сервисов не генерируем. Не добавляем ИИ-чат и хранение секретов. Не публикуем личные данные и не меняем соседние проекты. Публикация только на действующем `/kurs1/` с обратимым релизом. Незаконченные блоки остаются явно отмеченными, не объявляются выполненными.
