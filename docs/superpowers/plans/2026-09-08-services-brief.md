# Бытовые сервисы: задача исполнителю

Рабочая папка course-quest-academy. Прочитать `docs/audits/2026-09-08-beginner-track-review.md` строки 137–278 и `app/content/reviewed/planning.ts` как одобренный образец. Пользователь просит такие же содержательные исправления на всех треках; здесь только бытовые сервисы, кроме уже готового planner и family-health-hub (отдельный авторский шаблон).

Владение: только новые `app/content/reviewed/services.ts`, `app/content/reviewed/services.test.ts`, отчёт `docs/audits/2026-09-08-services-report.md`. Не трогать общую интеграцию/счётчики/прогресс. Не коммитить чужие файлы: в репозитории есть незакоммиченная работа. Вы не один в коде.

Экспорт `buildServiceLessons(project: ProjectDefinition, mode: DataMode, custom?: QuestCustomization): ReviewedLesson[] | undefined`. Тип ReviewedLesson импортировать из `./shared` (root создаёт): обязательные title, why, action, expected; частичные остальные QuestStep; дополнительно `legacyMilestone: number`. Возвращать undefined для не своих slug. Все 9 сервисов кроме planner: family-expenses, idea-vault, child-schedule, pressure-diary, fitness-tracker, recipe-book, personal-organizer, home-helper (проверить фактический перечень в projects.ts). Число шагов не унифицировать.

Сначала предметные падающие тесты, затем implementation. Прямо вызывать builder в тестах, без интеграции buildQuest. Нужны уникальные сценарии и ожидаемые конкретные значения (например бюджет 200+300=500, рецепт/поиск, перенос занятия). Реальные записи вводятся в готовую форму, не в чат ИИ; учебные проверки отдельно. Первая команда создаёт работающую локальную основу/ссылку, не только файлы или описание. Кастомизация после первого теста через customization:service. Проверки сохранения, ошибочного ввода, резервной копии, отсутствие публикации личных данных. Финальный шаг портфолио; клиентская практика будет добавлена root как extension автоматически. Не делать её обязательной. Ключи, медицинские советы, банковские интеграции, внешние календари и автоуведомления не добавлять. Минимум безопасности встроен предметно, без полотен одинаковых дисклеймеров.

legacyMilestone — номер старого этапа, завершение которого доказывает новый результат; читать старые сценарии, брать консервативно, монотонно. Root проверит миграцию отдельно. screenshot не назначать: root скрывает устаревшие снимки. Общие safety/rules/help/extension root добавляет. Тексты короткими абзацами, один смысловой этап, предметные кнопки в кавычках. Тесты запустить самостоятельно. Отчёт кратко: все slug и count, RED/GREEN, ограничения. Закончить самопроверкой каждого маршрута прежде следующего. Ничего не деплоить.
