# Искра — ответы внутри платформы

Подтверждено пользователем: использовать существующее API-подключение Феечки, а не новый Polza. Обнаружен MiniMax M3. Telegram, проекты, секреты и история бота не подключаются к модели Искры.

## План и границы

- [x] Тесты серверного чата: авторизация, CSRF, изоляция по аккаунту, идемпотентность, ограничения, отказ провайдера.
- [x] `services/neiroprofi-access/iskra.py`: отдельные таблицы истории/резервов, серверный ключ, только ответы, без инструментов. Контекст берётся из сгенерированной базы опубликованных уроков, а не клиентского system prompt.
- [x] `scripts/export-iskra-knowledge.mjs`: материал всех конкретных квестов, обоих форматов и Mac/Windows. Обновлять вместе с релизом.
- [x] `app/components/IskraChat.tsx`: вопрос, ответ, статус ожидания, сохранённая история аккаунта, ошибки без потери вопроса. Старые локальные заметки сохраняются отдельно.
- [x] Контекст текущего урока передавать как slug/номер/формат/ОС, без файлов и личных настроек проекта.
- [x] Проверить API, регрессии UI и сборку. Выпустить новую изолированную версию сервиса и статики на существующий `/kurs1/`, сохранив откат и закрытый вход.

Лимиты первого запуска: 20 запросов на аккаунт за UTC-день, 300 на платформу за день, 5 миллионов консервативно учтённых токенов за UTC-месяц. Не более двух одновременных запросов и одного от аккаунта. Неизвестный расход сохраняет резерв; автоматического повтора платного запроса нет. Это отдельный учёт Искры, баланс провайдера общий с Феечкой; лимиты Telegram не меняются.

История — только текущего аккаунта, до 20 сообщений на контекст; доступны последние 30 дней. Старый текст очищается при обращении к истории или отправке вопроса; метаданные расхода сохраняются. Email, коды входа и другие аккаунты в модель не передаются. Объяснение в интерфейсе: ИИ может ошибаться, вопросы обрабатывает внешний сервис, секреты и личные данные не отправлять. Это не обучение модели на переписках.

## Результат проверки

Все пункты выполнены. Прямой ответ MiniMax и authenticated HTTPS `/kurs1/access/api/iskra` проверены на рабочем сайте; повтор с тем же requestId вернул сохранённый ответ, история после запроса совпала. Проверочные сообщения скрыты из истории владельца, их расход не удалён. Временные проверочные сессии не меняли коды или прежние сессии.

База: 49 маршрутов, обе поверхности, Mac/Windows, плюс вводная маршрута. 1636 записей, экспорт без пользовательских данных. При изменении уроков выполнить `node scripts/export-iskra-knowledge.mjs` и включить новый JSON в релиз сервиса. Поиск лексический, не семантическая векторная база; общие слова о телефоне не должны рекомендовать посторонние проекты.

UI: 190 проверок выбранных файлов после последней сборки, 215 перед заключительными уточнениями. Серверная проверка включает сессии, CSRF, сохранение, изоляцию, лимиты, неопределённый расход и идемпотентность. Браузерное взаимодействие с реальным мобильным устройством отдельно не проверялось.

Публикация: статика `20260911-iskra-chat-r2`, сервис `20260911-iskra-chat-r3`. Начальный защищённый откат — `/root/neiroprofi-iskra-backup-20260911`, прежняя статика `20260910-iskra-install`, сервис `20260910-install-guide`. Не публиковать архивы БД или окружение. Не повторять одноразовый `deploy_iskra.py`: он намеренно отклоняет повтор.
