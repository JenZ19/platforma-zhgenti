# НЕЙРОПРОФИ: закрытый вход и управление доступами

Отдельный Python 3.12+ / SQLite сервис для `https://ezhgenti.ru/kurs1/`. Никаких внешних зависимостей. Не использует БД/секреты других курсов.

- `/kurs1/login` — почта + персональный случайный код.
- `/p/<адрес>` и `/s/<номер>` — **открытые** страницы: портфолио выпускницы и проверка сертификата. Вход не нужен, публикует их сама ученица.
- `/raboty` — **открытая** витрина: список тех портфолио, которые ученицы сами разрешили показывать. Единственная страница сервиса, открытая поисковикам по умолчанию.
- `/kurs1/admin` — управление ученическими доступами, только для администратора.
- `/kurs1/account` — свой доступ и выход.
- Все уроки, JS, картинки и ZIP-файлы закрыты через Nginx `auth_request`.
- Исключение: `/kurs1/manifest.webmanifest` и три точных пути `/kurs1/app-icons/iskra-{180,192,512}.png` — публичные имя и значки ярлыка, без учебных данных. Для публикации этой функции нужны и обновлённый `ui.html`, и Nginx snippet, и файлы из `public/`; один деплой фронтенда не обновит страницу входа. Значки пересобираются командой `node scripts/package-app-icons.mjs` из утверждённой Искры. Не добавлять офлайн-кэш уроков: он может обходить закрытие доступа.
- Сессии: 7 дней ученица, 8 часов администратор. Код 128 бит; в БД только HMAC. Перевыпуск кода отзывает все сессии пользователя.
- Из веб-админки невозможно создать администратора или изменить другого администратора.
- POST требует совпадения Origin и специального заголовка. Cookie HttpOnly/Secure/SameSite=Lax. Попытки входа ограничены в SQLite.
- Интерфейс не загружает сторонние ресурсы. Имена/почта отображаются через textContent.

## Границы первой версии

Это **не SSO и не автоматическая синхронизация GetCourse**. Проверенные активные покупки продукта 4454899, группы 4925213 импортируются вместе со сроком. Новые покупки, возвраты, отзыв VIP и изменения сроков администратор вносит вручную. Рассрочка при активном праве не исключается. Веб-форма добавления создаёт только ученицу.

Почта в форме — идентификатор, владение ею здесь не подтверждается. Секретный код нужно передать лично соответствующей участнице. У сервиса **нет почтового транспорта**, он не отправляет приглашения. Подтверждение доставки не подразумевается.

Редактора учебных материалов в этой версии админки нет.

## Учебный прогресс в аккаунте

Рабочее хранилище прогресса — по-прежнему браузер; в аккаунте лежит его копия, чтобы обучение переживало смену устройства и чистку кэша. Правило слияния одно: **где пройдено больше шагов, та запись и остаётся** — ни вход с нового ноутбука, ни возврат на старый телефон шаги не отнимают. Выбор проектов недели и карточки портфолио берутся из аккаунта в момент загрузки страницы, дальше уходит то, что делает ученица.

Синхронизация: при открытии платформы (получить → слить → отправить), затем через четыре секунды после каждой отметки шага и при уходе со вкладки. API — `GET/POST /kurs1/access/api/progress`, принимаются только учебные ключи (`sync.PREFIXES`/`sync.KEYS`), до 600 записей и 256 КБ. Ключ личной Феечки, сессии и что-либо ещё в копию не попадают.

Без входа синхронизация молча выключается: прогресс остаётся в браузере, как раньше.

## Вопросы куратору

Со страницы урока вопрос уходит в аккаунт вместе с проектом, шагом и устройством (`POST /kurs1/access/api/support`, action `ask`). Куратор видит очередь в `/kurs1/admin`, отвечает там же (`action: answer`), ученица читает ответ в разделе «Мои вопросы». Лимиты: не больше пяти вопросов без ответа и двадцати в сутки на ученицу.

Если в окружении задан `NP_CURATOR_CHAT`, о новом вопросе прилетает сообщение в Telegram куратора через бота школы; сбой отправки вопрос не теряет — он уже сохранён. Ученице о готовом ответе пишем, только если она подключила напоминания.

В списке учениц куратор видит, сколько шагов пройдено, сколько проектов начато, когда прогресс синхронизировался последний раз и сколько вопросов ждут ответа.

## Календарь шести недель

Ученица сама отмечает день старта («Начинаю сегодня»); неделя считается как семь суток от этой отметки, после шестой маршрут считается пройденным. Календарь ничего не закрывает: все уроки открыты всегда. Ученица может сдвинуть отсчёт на сегодня или убрать календарь совсем. API — `GET/POST /kurs1/access/api/course`.

## Витрина работ и индексация

Публикация страницы и показ в витрине — два разных решения ученицы. По умолчанию опубликованная страница `/p/<адрес>` открыта только по прямой ссылке и закрыта от поисковиков, как раньше. Галочка «показывать в витрине» добавляет её в список на `/raboty`; вторая галочка — «разрешить поисковикам» — снимает `noindex` с её собственной страницы. Вторую нельзя включить без первой: иначе страницу нашли бы поисковики, а со страниц школы на неё не было бы ни одной ссылки.

Куратор может убрать страницу из витрины, не снимая её с публикации: `POST /kurs1/access/api/moderate` с `moderation: unlist`. Полное закрытие (`unpublish`) заодно сбрасывает обе галочки — повторная публикация снова спрашивает согласие. Все три действия пишутся в журнал.

Сама витрина отдаётся поисковикам всегда и не показывает ни почты, ни служебных полей — только имя, строку «чем помогаю» и ссылку на страницу.

## Портфолио и сертификат

Карточки работ по-прежнему заполняются в браузере. При публикации выбранные карточки копируются в аккаунт и отдаются открытой страницей `/p/<адрес>`: имя, «чем помогаю», о себе, один контакт и до восьми работ с честным статусом. Почта ученицы на странице **не показывается**. Адрес занимается за аккаунтом, повторно занять его нельзя. Снять с публикации может сама ученица и куратор.

Сертификат выдаётся, когда ученица опубликовала портфолио с тремя работами и сообщила, что закрыты все шесть недель. Отметки о прохождении приходят из браузера — сервер их не перепроверяет, поэтому это сертификат школы о прохождении, а не документ государственного образца; формулировка на странице это прямо говорит. Номер вида `NP-ГОД-ПОРЯДКОВЫЙ`, проверка — `/s/<номер>`. Куратор может отозвать сертификат и закрыть открытую страницу в админке (`POST /kurs1/access/api/moderate`), действие пишется в журнал.

Это открытые страницы на домене школы: перед первым потоком договоритесь, что делать с неуместным содержимым, и проверяйте журнал в админке.

## Напоминания о неделе в Telegram

Сообщения идут через **общего бота школы @feyakrestnayasbm_bot** (Фея-крёстная). Его опрашивает свой проект на 89.35.129.254; здесь мы **только отправляем** сообщения. Второй `getUpdates` по тому же токену сломал бы её: Telegram отдаёт 409. Поэтому команд боту у напоминаний нет, подключение и отключение — в платформе.

Подключение: ученица отправляет Фее-крёстной `/myid`, вставляет число в настройках платформы, сервис шлёт в тот же чат шестизначный код, ученица вводит его. Код живёт 30 минут, попыток — пять в час, чужой Telegram ID так не подключить. Один чат обслуживает один аккаунт.

Рассылок две. Понедельничная — в 10:00 по Москве, по одному сообщению на аккаунт в неделю: какая идёт неделя, а после шестой — напоминание про портфолио и сертификат. Молчит, если доступ закрыт или истёк, если календарь не начат и если ученица заблокировала бота (тогда привязка снимается).

Четверговая — мягкий пинг тем, у кого отметки уроков стоят четыре дня и больше (`weeks_bot.py nudge`, юниты `neiroprofi-weeks-nudge.service` + `.timer`, четверг 12:00 по Москве). Он молчит, если ученица ещё ничего не отмечала, если её вопрос уже ждёт ответа куратора и если такой же пинг уже уходил, а шагов с тех пор не прибавилось; повтор — не чаще раза в десять дней. Сообщение не подгоняет, а напоминает про кнопку «Спросить куратора» и предлагает подвинуть отсчёт недель.

Установка: в `/etc/neiroprofi-access/env` положить `NP_REMINDER_BOT_TOKEN` (токен Феи-крёстной) и `NP_REMINDER_BOT=feyakrestnayasbm_bot`. Без токена платформа честно отвечает, что напоминания школой не подключены. Юниты: `neiroprofi-weeks-send.service` + `.timer`, `neiroprofi-weeks-nudge.service` + `.timer`. Перед включением таймера проверить `systemd-analyze calendar "Mon *-*-* 10:00:00 Europe/Moscow"` — строка с часовым поясом требует systemd 252+. Разовый прогон: `python3 weeks_bot.py send`.

Токен общий с чужим сервисом: при его смене обновлять обе машины. Своего опроса и вебхука здесь заводить нельзя.

⚠️ Путь от 91.200.84.230 до `api.telegram.org` рвётся волнами: в плохие минуты виснет больше половины соединений, в хорошие проходит почти всё; удачное соединение занимает сотые доли секунды, неудачное — весь таймаут. Поэтому отправка чередует два независимых маршрута и делает четыре короткие попытки: `neiroprofi-telegram-tunnel.service` держит SSH-проброс `127.0.0.1:8443 → api.telegram.org:443` через Hetzner 178.104.182.101 (ключ `/etc/neiroprofi-access/tunnel_key`, на той стороне ограничен `restrict,port-forwarding,permitopen`), а запасной путь — прямое соединение. TLS сквозной, Hetzner видит только шифрованный поток. Каталог `/etc/neiroprofi-access` — `750 root:neiroprofi-access`, иначе служба не прочитает ключ. Если откажут оба маршрута, ученица видит честную ошибку, а рассылка оставляет неделю неотмеченной и повторит её в следующий запуск.

## Размещение

Гайд «Добавить Нейропрофи на экран телефона» использует общий `home-screen-guide.json`: React показывает его на главной, а `home_screen_guide.py` — на странице входа. При обновлении сервиса переносить оба файла вместе с `access.py` и `ui.html`. Четыре обрезанных изображения в `public/home-screen-guide/` доступны через точные публичные Nginx-пути; исходные скриншоты с контактами не копировать в релиз.

Сервис: `/opt/neiroprofi-access/current`, порт 8799 (только loopback).
БД: `/var/lib/neiroprofi-access/access.sqlite3`.
Окружение: `/etc/neiroprofi-access/env`, права 600.
Переменные: NP_DATABASE, NP_SECRET (случайный секрет >=40 символов), NP_ORIGIN=https://ezhgenti.ru, NP_PORT=8799, NP_REMINDER_BOT и NP_REMINDER_BOT_TOKEN (напоминания), NP_CURATOR_CHAT (куда сообщать о вопросах), NP_TELEGRAM_VIA (локальный порт туннеля), NP_ISKRA_KEY_FILE (Искра).
Процесс: `neiroprofi-access.service`, пользователь `neiroprofi-access`.
Nginx snippet: `/etc/nginx/snippets/ezhgenti-kurs1.conf`. В нём же открытые локации `^~ /p/`, `^~ /s/` и `= /raboty` без `auth_request` — единственные адреса сервиса, доступные без входа; `client_max_body_size` для `/kurs1/access/` поднят до 32k ради формы портфолио.

Запуск тестов: `python3 -m unittest discover -s services/neiroprofi-access -v`.

CLI `access.py import --input /private/import.json --output /private/new-codes.csv` принимает массив email/name/gc_id/expires (Unix seconds), использует серверное окружение. Не хранить этот JSON или CSV в Git/публичной папке. Повторный импорт не перевыпускает коды и не восстанавливает отозванных учениц. Не применять импорт для массового отзыва: это отдельное осознанное действие.

CLI `access.py admin --email EMAIL --name NAME --output /private/admin-code.csv` — только для прямо одобренного владельцем администратора. Коды никогда не печатаются в журнал.

Бэкап SQLite делать sqlite3 backup API, не копированием открытого WAL-файла; хранить с правами 600 вне webroot. Секрет сохранить отдельно: без прежнего секрета коды/сессии станут недействительны. Для отката неисправного сервиса сохранять закрытый вход: не возвращать публичный Nginx без явного решения владельца.
